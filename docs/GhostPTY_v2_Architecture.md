# GhostPTY v2: 幽灵网格 (Ghost Grid) 架构蓝图与开发计划书

**作者:** GhostPTY 首席安全架构组
**代号:** Timeless Aegis (无时域之盾)
**目标愿景:** 将 GhostPTY 从单点堡垒机升维至 Web3 / DePIN 领域的新一代 L1 级去中心化基础设施访问协议层。

---

## 摘要 (Executive Summary)

GhostPTY v2 不仅仅是一个安全工具的迭代，它是网络安全底层范式的重构。
针对现有中心化单点故障、NTP 依赖、以及物理延迟带来的种种协议级漏洞，v2 提出了一种**“无时域密码学状态机 (Timeless Cryptographic State Machine)”**的底层哲学。

核心突破点在于：
1. **彻底摒弃物理时间依赖**，用事件序列与哈希链因果律重构 SPA 防重放与会话生存周期。
2. **非对称双层防御**，用 eBPF 的极致性能抵御 L3/L4 泛洪，用用户态 QUIC 的精算能力完成 L7 业务闭环。
3. **去中心化授权网格**，通过 Gossip 协议和 CRDT 算法实现全球节点秒级策略同步与拜占庭容错。

---

## 第一层：基础引擎革新 (The Data Plane Upgrade)

本阶段聚焦于单节点 eBPF 数据平面的内核级重构，实现极端的性能与无时域敲门验证。

### 1.1 哈希链验证器 (Hash Chain Verifier)

*   **当前痛点**: 基于 OTP / Timestamp 的包极易受 NTP 劫持与乱序丢包影响。
*   **革新方案**: 引入 **Lamport S/KEY 现代化哈希预像链**。
    *   客户端在建立初始连接时锚定终点哈希 $H_N$ 至控制面。
    *   每次 UDP 敲门使用 $H_{N-x}$。
*   **工程细节 (eBPF)**:
    *   在 XDP 层实现带序号的 $O(1)$ 查找：`[Seq: N-x, Hash: H_N-x]`。
    *   利用 `#pragma unroll 10` 在内核执行受界有向循环，容忍最大 10 个 UDP 丢包的乱序快进，维护因果链韧性。
*   **产出指标**: XDP 解析与放行验证时间压缩至 500ns 以内，彻底免疫重放攻击与时钟漂移。

### 1.2 物理级防伪造限流 (XDP Rate-Limiting Token Bucket)

*   **当前痛点**: 伪造源 IP (IP Spoofing) 会轻易触发后端（甚至 eBPF 现有逻辑）的无效状态操作，导致“拒绝钱包 (Denial of Wallet)”攻击。
*   **革新方案**: 在 `ALLOW_LIST_MAP` 基础上叠加硬件级资源分配视角。
*   **工程细节 (eBPF)**:
    *   每个合法的 DID IP 绑定一个轻量级的 eBPF `bpf_spin_lock` 保护的令牌桶计数器。
    *   **策略**: 对于源 IP 在白名单中的海量垃圾突发流，直接在网卡驱动层执行软限流（`XDP_DROP`），使其永远无法触及业务层的配额计费系统。

## 第二层：核算与通信中枢 (The Comm & Settlement Layer)

本阶段聚焦于用户态的 `quinn` 服务器重构，实现与底层 eBPF 的精准联动闭合，以及与外部世界的高维隔离。

### 2.1 会话燃尽计费系统 (Burn-rate Metering)

*   **当前痛点**: 依靠“TTL 超时”来切断连接，逻辑粗放，无法精确控制高危访客的交互深度。
*   **革新方案**: 用“密码学消耗量”替代“物理时间流逝”。
*   **工程细节 (Rust + Quinn)**:
    *   依靠 QUIC 层 TLS 1.3 的 AEAD 特性，只有被成功解密、真正属于目标 DID 的字节才会被计入使用配额 (Quota)。
    *   一旦会话配额（如 10MB 指令流或 1000 个逻辑轮次）耗尽，用户态直接调用系统接口下令 eBPF 清除该 IP 退网，实现**“鉴权后计费与燃尽即物理拔网线”**的闭环。

### 2.2 逻辑心跳质询 (Causal Heartbeat)

*   **革新方案**: 不依赖基于时间的超时踢人，而是由服务端在 QUIC Control Stream 内发起非常规且非物理定期的“密码学随机质询（Nonce + Ed25519 签名验证）”。客户端无响应或错签即视为死连接剔除。

## 第三层：全球控制面与共识建立 (The Global Control Plane)

这是 GhostPTY 从“堡垒机组件”向“Web3 去中心化 L1 协议”跨越的核心战役。数百个承载该协议的边缘节点将连成一张不可摧毁的幽灵网。

### 3.1 去中心化状态同步 (Gossip State Sync)

*   **架构选型**: 摒弃中心化的 Redis/Etcd/PostgreSQL 控制面板。
*   **技术栈**: 集成 `libp2p (GossipSub v1.1)` 协议。
*   **数据流转**: 当任一边缘节点（如 Node A）接收到合法的 SPA/哈希链第一击后，立即生成极简序列化包（Protobuf / Bincode）并极速广播至全网。包内容涵盖：`[Event_Type, DID, IPv4_Hash, TTL/Quota, Sequence, Issuer_Sig]`。
*   **内核级热扩散**: Node B 收到 Gossip 广播、光速验签后，直接将其注入自身的内核 `ALLOW_LIST_MAP`。授权从单点敲击演变为全网泛洪开门。

### 3.2 拜占庭容错与多签背书 (BFT & Threshold Signatures)

*   **防内鬼机制**: 针对诸如 `SLASH` (物理封杀/剥夺授权) 等高危全局指令，节点间需形成“门限共识 (Threshold Consensus)”。
*   **执行逻辑**: 单一被攻陷节点的恶意广播不具备执行效用；必须收集到 `m-of-n` (如 3 个以上验证节点) 针对同一审计铁证哈希事件的联合签名，Gossip 网络才会将其升格为“共识决议”，进而指令全网 eBPF 封杀该目标 DID。

### 3.3 并发双花防御 (CRDT & Quota Sharding)

*   **痛点**: 恶意并发消耗配额 (`Double-Spend`)。
*   **缓解策略 (V2.0 初期)**:
    基于 CRDT (无冲突复制数据类型) 进行乐观全局记账。各节点允许先放行、后结账。全网汇聚计量时，若发现总量超额，则激活终极惩罚机制：触发全球 `SLASH`。

## 阶段实施路线图 (Roadmap)

GhostPTY v2 的重构是一次心脏移植手术，必须分层、稳妥地进行。

**Phase 1: 数据平面抗丢包升级 (内核重构)**
* 交付物: 使用明文 `Seq` + 嵌套哈希取代传统 SPA 的时间戳，完成 eBPF 内部 `#pragma unroll` 哈希链验证引擎的重写。
* 验收标准: 模拟 30% UDP 恶劣丢包乱序环境下，合法敲门 100% 稳定上岸无延误。

**Phase 2: 核算引擎的闭环重设计 (协议脱水)**
* 交付物: 从系统中剥离一切与 NTP 相关的 TTL / Timeout 设计，重构 `quinn` 服务端代码，全面接入基于 AEAD 的会话燃尽 (Burn-rate) 系统。
* 验收标准: 发送海量伪造源 IP 垃圾包进行压测，用户态核算进程 0 波动，10GB 配额控制误差在 10KB内。

**Phase 3: 幽灵网格启动 (雏形共识)**
* 交付物: 引入 `libp2p` 库，建立硬编码的极小规模（3 节点）Gossip 测网，实现单节点敲门，三节点 eBPF Map 微秒级联动同步授权。
* 验收标准: 全局状态收敛一致。

## 愿景结语 (Architectural Statement)

时间不过是人类用来测量熵增的幻象。真正的去中心化安全基础设施，不应相信时钟，而应信仰因果、密码学承诺与客观物理定律。GhostPTY v2，即为这一理念的终极武装化体现。
